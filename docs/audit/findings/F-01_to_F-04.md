## 1. Finding F-01 (High): First-Contact Identity Anchor Bypass in Python KEX

### 1.1 Description and Root Cause
In `hybrid_kex_legacy.py` (`HybridKeyExchange`), `self.authorized_peer_fingerprints` was uninitialized in `__init__`. In `HybridKeyExchange.verify_public_bundle(bundle)`:
```python
if pin_status == 'new':
    auth_fps = getattr(self, 'authorized_peer_fingerprints', None)
    if auth_fps is not None and fingerprint not in auth_fps:
        ... reject ...
```
Because `self.authorized_peer_fingerprints` was `None` by default, `auth_fps is not None` evaluated to `False`. Under production posture, unknown peer identities bypass authorization checks and are accepted on first contact without an explicit trust anchor or enrolled fingerprint. Furthermore, `verify_public_bundle` did not commit accepted pins atomically.

### 1.2 Remediation
1. **Initialize Trust Anchor Whitelist**: `HybridKeyExchange.__init__` accepts `authorized_peer_fingerprints: Optional[Any] = None` and initializes `self.authorized_peer_fingerprints`.
2. **Fail-Closed Production Policy**: In `verify_public_bundle`, if `pin_status in ('new', 'unpinnable')` under strict/production posture (`is_production()` or `P2P_STRICT_SECURITY=1`), verification fails closed unless the peer's SHA3-512 fingerprint is explicitly present in `authorized_peer_fingerprints` or `P2P_AUTHORIZED_PEER_FINGERPRINT`.
3. **In-Memory vs Persistent Scope Separation**: `in_memory_only=True` instances maintain pins in `self._in_memory_pins`, preventing cross-test pollution of `~/.secure_p2p/pins.json`. `in_memory_only=False` instances persist pins via `ui.safety_numbers.store_pin`.
4. **Atomic Pin Commit**: Pin storage occurs strictly after all cryptographic signatures (Ed25519 prekey signature and FALCON bundle signature) have successfully verified.

### 1.3 Verification
- Dedicated test suite `tests/test_f01_identity_anchor.py`:
  - `test_f01_unauthorized_first_contact_rejected_in_production`: verified unknown peer is rejected when unanchored.
  - `test_f01_authorized_first_contact_accepted_and_pinned_in_memory`: verified enrolled peer is accepted and pinned in memory.
  - `test_f01_authorized_first_contact_accepted_and_pinned_persistently`: verified enrolled peer is accepted and stored to disk pin store.
- Existing suite `tests/test_falcon_bundle_mode_consistency.py`: 7/7 passed.

## 2. Finding F-02 (Medium): Group Ratchet Premature Key Destruction Before AEAD Tag Verification

### 2.1 Description and Root Cause
In `rust_data_plane/src/group_ratchet.rs` (`decrypt_group_message`), when handling out-of-order delivery from the skipped-message-key cache:
```rust
let lookup_key = (sender_id.to_string(), epoch, seq);
if let Some(skipped_msg_key) = self.skipped_message_keys.remove(&lookup_key) {
    let plaintext = cipher.decrypt(&nonce, Payload { msg: ciphertext, aad: &aad })
        .map_err(|_| GroupError::AuthenticationFailed)?;
    return Ok(plaintext);
}
```
`self.skipped_message_keys.remove(&lookup_key)` executed before `cipher.decrypt(...)` validated the AES-GCM authentication tag. If an attacker injected a forged ciphertext with a sequence number matching a cached skipped key, the legitimate key was permanently removed. Subsequent arrival of the genuine message caused decryption failure (`SequenceMismatch`), yielding an unrecoverable state-destruction denial-of-service.

### 2.2 Remediation
1. **Borrow/Clone Before Verification**: Replace `self.skipped_message_keys.remove(&lookup_key)` with `self.skipped_message_keys.get(&lookup_key).cloned()`.
2. **Atomic Commit On Tag Pass**: Remove the cached entry from `self.skipped_message_keys` strictly after `cipher.decrypt(...)` succeeds. If decryption fails, the skipped key remains cached for the genuine message.

### 2.3 Verification
- Added test in `rust_data_plane/src/group_ratchet.rs`:
  - `test_f02_skipped_message_key_survives_forged_auth_failure`: frame 1 arrives out of order, caching key for seq 0. A forged frame for seq 0 with corrupted AEAD tag fails authentication (`Err(AuthenticationFailed)`). Bravo's skipped key cache remains populated (`len() == 1`). The genuine frame 0 arrives and decrypts successfully.
- Full cargo verification:
  - `cargo clippy --manifest-path rust_data_plane/Cargo.toml --all-targets -- -D warnings`: 0 warnings (exit 0).
  - `cargo test --manifest-path rust_data_plane/Cargo.toml`: 187/187 tests passed.

## 3. Finding F-03 (Medium–High): Python Noise Session Incomplete Secret Lifecycle Cleanup

### 3.1 Description and Root Cause
In `noise_pq.py` (`NoiseSession.destroy()` and `NoiseSession.quarantine()`):
- Mutable transport key buffers (`_f_sk`, `_f_ss`, `_k_send`, `_k_recv`, `psk`) were unlocked and zeroized, but `self.sig_sk` (long-term ML-DSA-87 private signing key) and `self._e_priv` (P-384 ephemeral private key object) were retained on the instance.
- Quarantine called `destroy()`, leaving private key references alive.

### 3.2 Remediation
1. **Signing Key Cleanup**: In `destroy()`, if `self.sig_sk` is a `bytearray`, unlock and zeroize in-place via `_unlock_buffer` and `_zero`; explicitly set `self.sig_sk = None`.
2. **Ephemeral Private Key Cleanup**: Explicitly set `self._e_priv = None`.
3. **Quarantine Freeze**: In `quarantine()`, execute `self.destroy()` and explicitly wipe public metadata references (`handshake_hash = None`, `sig_pk = None`, `_e_pub = None`, `_peer_sig_pk = None`) while latching `self._quarantined = True`.

### 3.3 Verification
- Added test in `tests/test_noise_pq_purity.py`:
  - `test_f03_noise_session_sig_sk_and_epriv_destroyed`: verified that after `destroy()` or `quarantine()`, `sig_sk`, `_e_priv`, and `sig_pk` are cleared and mutable signing key buffers are zeroized in-place.
- Full test pass:
  - `pytest tests/test_noise_pq_purity.py`: 12/12 passed.
  - `pytest tests/test_noise_pq_hardened.py`: 21/21 passed.

## 4. Finding F-04 (Medium): Branch Protection and CI Gate Hardening

### 4.1 Description and Root Cause
The default GitHub branch (`main`) lacked branch protection rules requiring:
- Passing status checks from `.github/workflows/defense_ci.yml` before merge.
- Required pull request reviews.
- Signed commits (`commit.gpgsign = true`).

### 4.2 Recommended Repository Settings (Human Administrator Action)
Under the repository authority boundaries (agent is restricted from altering GitHub repository settings directly), the following branch protection policy must be configured on `https://github.com/Destroyer-official/Destroyer-ST2027`:
1. **Branch Protection Rule on `main`**:
   - Require a pull request before merging (minimum 1 approving review).
   - Require status checks to pass before merging:
     - `Defense CI / Rust & Python Zero-Gap Military Verification`
     - `cargo clippy --all-targets -- -D warnings`
     - `verify_deployment.py`
   - Require branches to be up to date before merging.
   - Require signed commits.
   - Do not allow bypass of the above settings for administrators.
