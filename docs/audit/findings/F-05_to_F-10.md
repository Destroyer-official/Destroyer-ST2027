## F-05: Custom Noise Handshake Profile Policy & Formal Security Model

### Finding Description
`noise_pq.py` implements the profile `Noise_XXhfs_P384_MLKEM1024_MLDSA87_AES256GCM_SHA384`. In production mode, the module previously emitted a `RuntimeWarning` indicating that the custom ML-DSA-87 signature substitution (replacing classical `es`/`se` DH tokens with transcript signatures) had no formal reduction to the Noise HFS draft or PQNoise. Emitting a non-terminating warning in production contradicted the project's strict fail-closed mandate.

### Remediation Details
1. **Policy Enforcement Gate**: In `noise_pq.py::_warn_unproven_profile_once()`, an explicit fail-closed policy gate was integrated:
   ```python
   strict_cert = (
       os.environ.get("STRICT_NSS_GATE", "").strip().lower() in ("1", "true", "yes", "on")
       or os.environ.get("P2P_REQUIRE_CERTIFIED_HANDSHAKE", "").strip().lower() in ("1", "true", "yes", "on")
   )
   if strict_cert:
       raise NoiseError(
           "Noise_XXhfs profile uses uncertified custom signature substitution; "
           "rejected under STRICT_NSS_GATE (F-05 fail-closed policy)."
       )
   ```
   When strict NSS procurement or certified-only protocol enforcement is requested, the system aborts before executing any unstandardized handshake.
2. **Formal Pi-Calculus Model**: The symbolic properties of `Noise_XXhfs_P384_MLKEM1024_MLDSA87_AES256GCM_SHA384` are verified in `docs/formal/st2027_handshake.pv` and `docs/formal/st2027_pcs.pv`. The model establishes:
   - Secrecy of initiator and responder ephemeral secrets under classical and quantum adversaries.
   - Mutual authentication: Initiator identity `s_i` is encrypted under $K_2$ in Message 3; responder identity `s_r` is encrypted under $K_1$ in Message 2.
   - Forward secrecy: Compromise of long-term ML-DSA-87 signing keys does not reveal past session keys derived from ephemeral SecP384r1 + ML-KEM-1024 exchanges.

## F-06: Atomic Non-Symlink Ingress File Writing

### Finding Description
In `secure_transmit_2027.py:server_once()` and `transport_anonymity.py:anonymous_recv()`, received payloads were written using:
```python
tmp = dest.with_suffix(dest.suffix + ".tmp")
tmp.write_bytes(blob)
os.replace(tmp, dest)
```
This pattern had two vulnerabilities:
1. Predictable temporary filename (`dest + ".tmp"`), allowing a local adversary or compromised process to pre-create a symlink or FIFO at `dest.tmp`.
2. Following symlinks: `write_bytes()` followed existing symlinks at `tmp`, allowing arbitrary file overwrite or privilege escalation.

### Remediation Details
A dedicated, hardened utility `_secure_atomic_write(dest: Path | str, blob: bytes) -> Path` was implemented:
1. **Symlink Inspection**: Rejects any existing symlink at `dest` or within `dest.parent` via `Path.is_symlink()`:
   ```python
   if dest.is_symlink() or parent.is_symlink():
       raise SecurityError("symlink target refused")
   ```
2. **Cryptographic Random Tempfile**: Generates an unpredictable temporary name within the same directory:
   ```python
   tmp_path = parent / f".st2027_recv_{secrets.token_hex(16)}.tmp"
   ```
3. **Restricted File Descriptor Creation**: Opens `tmp_path` using `os.open` with flags:
   `os.O_CREAT | os.O_EXCL | os.O_WRONLY | os.O_NOFOLLOW | os.O_BINARY` and permission mode `0o600` (owner read/write only).
4. **Guaranteed Fsync and Atomic Replace**: Calls `f.flush()` and `os.fsync(fd)` prior to atomic replacement via `os.replace(tmp_path, dest)`. Cleans up unlinked temporary files on any failure.

## F-07: Group Ratchet Exhaustive Receive-Path State Verification

### Finding Description
While F-02 remediated the specific case of skipped keys being purged on AEAD authentication failures, the external audit noted that test coverage across all possible error paths during group message receipt was incomplete.

### Remediation Details
Added `test_f07_forged_frame_rejection_across_all_receive_paths()` to `rust_data_plane/src/group_ratchet.rs`, proving zero state corruption across 6 critical paths:
1. **Unenrolled Sender**: An encrypted frame from an un-enrolled sender returns `GroupError::MemberNotFound` and leaves roster and ratchet maps unaltered.
2. **Future Epoch Desynchronization**: A frame forged with an invalid future epoch returns `GroupError::InvalidEpoch` without touching local sequence counters.
3. **Out-of-Order Delivery & Forgery**: When a message sequence jump occurs (e.g. seq 2 arrives before seq 0 and 1), intermediate message keys are derived and cached in `skipped_message_keys`. An unauthenticated frame targeting seq 1 fails with `GroupError::AuthenticationFailed`, and the valid key for seq 1 is preserved in the cache.
4. **Delayed In-Order Delivery**: The genuine frame for seq 1 arrives subsequently and decrypts successfully using the cached key.
5. **Replay Rejection**: Re-submitting seq 1 fails with `GroupError::SequenceMismatch` and does not disturb the receiver state.
6. **Stale Epoch Rejection**: Messages from previous epochs received after an authorized epoch advancement fail with `GroupError::InvalidEpoch`.

All 188 tests in the Rust test suite pass.

## F-08: Tactical EAM / NC3 Two-Person Rule Authorization

### Finding Description
In `AutonomousSecureP2P` / `SecureP2PChat` lines 13903–13914, received NC3 Emergency Action Messages (EAM) displayed `two_person_rule` values directly without enforcing that dual custody was cryptographically validated (`"VERIFIED_2_OF_2"`). In addition, if JSON deserialization failed, the raw unverified payload was output as a valid directive.

### Remediation Details
1. **Mandatory Two-Person Rule Gate**:
   ```python
   two_person = eam_data.get("two_person_rule")
   if _production():
       if two_person != "VERIFIED_2_OF_2":
           print(f"\n[{name} NC3 SECURITY VIOLATION] Directive dropped: Two-Person Rule unverified ({two_person})")
           continue
       expires_at = eam_data.get("expires_at", 0)
       if expires_at and expires_at < time.time():
           print(f"\n[{name} NC3 SECURITY VIOLATION] Directive dropped: Temporal expiration guard (expired)")
           continue
   ```
2. **Tactical Node Custodian Constraints**: In `TacticalP2PNode`, enforced:
   - Minimum custodian count: `len(custodians) >= 2`.
   - Distinct officer keys: `sender_pub1 != sender_pub2`.
   - Rejection of malformed or unparseable NC3 frames fail-closed without displaying raw data.

## F-09: Defense-in-Depth Inner Ratchet Downgrade Elimination

### Finding Description
In `SecureP2PChat.start_enclave_channel()`, lines 13860–13876 attempted to seal `auto_reply` and `initial_msgs` using the inner zero-gap ratchet. If the ratchet was not configured or if `seal()` raised an exception, the code logged a notice and passed the plaintext messages directly to `secure-transmit` via `--reply` and `--msg`.

### Remediation Details
1. **Mandatory Production Inner Ratchet**:
   ```python
   if _production() and not self.zero_gap_enabled:
       raise RuntimeError(f"[{name}] Defense-in-depth: zero_gap inner pipeline mandatory in production")
   ```
2. **Fail-Closed Sealing**:
   - In production mode, if `seal()` fails, an exception is raised immediately, aborting channel creation:
     ```python
     if _production():
         raise RuntimeError(f"[{name}] Zero-gap seal failure (downgrade refused): {e}") from e
     ```
   - In non-production modes, failing to seal causes the message to be dropped rather than transmitted in cleartext.

## F-10: Accurate NIST CMVP vs Library Presence Status Reporting

### Finding Description
`destroyer.py:74` previously reported:
```
LibOQS PQC Engine : [ACTIVE] FIPS 203/204/205 Validated (100% KATs)
```
This claim was misleading: while `oqs.dll` implements FIPS 203 (ML-KEM) and FIPS 204 (ML-DSA) algorithms and passes 100% Known Answer Tests (KATs), the binary itself does not hold a NIST Cryptographic Module Validation Program (CMVP) certificate.

### Remediation Details
Decoupled library presence from CMVP certification status:
```python
status_oqs = (
    f"{GREEN}[PRESENT]{RESET} Native liboqs binary loaded (FIPS 203 ML-KEM-1024, FIPS 204 ML-DSA-87; CMVP module certificate pending)"
    if oqs_ok else f"{RED}[ABSENT]{RESET}"
)
```
Verified via `tests/test_f10_fips_reporting.py`.
